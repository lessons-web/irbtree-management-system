# 移除 Auth 页面并收敛为默认演示态设计

## 背景

当前项目的认证体系本质上是原型态演示认证，存在两条并行入口：

- 页面登录：`/auth` 页面中的“进入演示系统”按钮
- 弹窗登录：Header 的“登录 / 注册”按钮与受保护操作触发的登录弹窗

与此同时，课程页、推荐页、个人页和后台路由仍被 `RequireAuth` / `RequireRole` 包裹，未登录访问时会跳转到 `/auth`，并依赖 `state.from` 在登录后回跳。

但当前系统没有真实认证、角色切换或持久化会话，登录行为只是把前端内存态切到一个固定演示用户。因此：

- 用户首次进入系统时会被认证壳层打断
- 代码同时维护“页面登录”和“弹窗登录”两套路径
- 大量与“未登录拦截”相关的逻辑只是在服务原型态过渡方案，而不是业务本身

本次工作的目标是移除 `auth` 页面及其对应链路，让整个系统默认以可访问的演示态运行。

## 目标

- 删除 `auth` 页面，不再渲染或暴露登录页 UI
- 去掉原有用户端与后台的登录守卫，默认直接可访问
- 移除“未登录跳转 `/auth`”和“登录后回来源页”的逻辑
- 下线登录弹窗、Header 登录按钮以及相关受保护操作封装
- 让系统以固定演示用户态直接运行，保持现有页面展示完整性

## 非目标

- 不接入真实账号体系
- 不新增注册、找回密码或权限管理功能
- 不重做用户端和后台的视觉设计
- 不改变现有课程、推荐、评课、后台等页面的业务内容
- 不在本次引入持久化登录或 Cookie / Token 机制

## 验收口径

本次改造完成后，应满足以下结果：

- 访问 `/`、`/courses`、`/course/:code`、`/recommendation`、`/profile`、`/learn`、`/admin` 时都不再因为未登录而跳到 `auth`
- 项目内不再存在可见的 `AuthPage`
- 页面与组件中不再出现“进入演示系统”“登录”“注册”“请先登录”等认证入口或拦截流程
- `/auth` 不再作为独立页面存在；如保留兼容入口，也只做无感跳转而不渲染登录页
- 用户端 Header 与后台仍能展示完整的用户信息与菜单，不因移除认证而出现空态断裂

## 设计原则

### 1. 演示可用优先

项目当前是前端演示系统，认证不承担真实安全边界。本次以“直接进入可操作界面”为优先目标，不再让演示认证阻断核心浏览与操作路径。

### 2. 删除双轨认证链路

页面登录和弹窗登录本质上在做同一件事，即把内存态用户切到一个固定原型账号。本次一次性移除两条链路，避免留下半套入口。

### 3. 保持用户展示连续性

虽然移除了认证，但页面上的用户头像、名字、Admin 入口、个人中心等展示仍应保留。因此不把用户态完全删空，而是收敛为固定演示会话。

### 4. 最小行为变更

本次不对具体业务页的内容、字段和交互做额外修改。重点只落在路由、守卫、Header、登录弹窗和演示用户状态来源。

## 方案选择

本次采用「删除认证入口 + 默认固定演示用户 + 放开全部原受保护路由」方案。

### 备选方案

- 删除 `/auth` 页面，但保留登录弹窗
- 删除 `/auth` 页面，并在未登录时统一打回首页

### 不采用原因

保留登录弹窗仍然意味着保留认证链路和“先拦截再进入”的心智，不符合“移除对应逻辑”的目标；统一打回首页则继续保留未登录概念，且会降低演示可达性。

因此，本次确定：

- 不再保留未登录态拦截
- 不再保留登录入口
- 直接让系统以固定演示用户运行

## 影响范围

本次主要影响以下文件：

- `src/app/router.tsx`
- `src/pages/auth/AuthPage.tsx`
- `src/features/auth/guards.tsx`
- `src/features/auth/AuthContext.tsx`
- `src/features/auth/state.ts`
- `src/components/user/UserHeader.tsx`
- `src/components/user/LoginModal.tsx`
- `src/components/user/UserOverlayContext.tsx`
- `src/features/auth/useRequireAuthAction.ts`
- `src/features/auth/useProtectedNavigation.ts`
- `src/app/router.test.tsx`
- 其他与认证拦截、登录入口相关的测试文件

其中：

- 路由层负责移除 `auth` 页面与守卫接入
- 状态层负责把用户来源收敛为固定演示用户
- 组件层负责删除登录入口、登录弹窗和相应交互
- 测试层负责同步更新默认访问行为

## 路由设计

### 用户端路由

原先被 `RequireAuth` 包裹的用户端页面改为直接挂载：

- `/courses`
- `/course/:code`
- `/recommendation`
- `/profile`
- `/learn`

这些页面不再需要先经过登录态检查。

### 后台路由

原先由 `RequireRole` 包裹的 `/admin` 路由改为直接可进入：

- 不再进行“未登录跳 `auth`”
- 不再进行角色拦截
- 后台继续以固定演示用户身份展示

### 兼容路径

`/auth` 不再作为真实页面存在。为了避免旧链接或旧测试直接报错，本次保留一个兼容跳转：

- `/auth` 直接重定向到 `/`
- 不再渲染 `AuthPage`

这意味着系统对旧入口保持兼容，但语义上已经没有独立登录页。

## 状态设计

### 演示用户

`AuthProvider` 收敛为固定演示会话提供者：

- 应用启动后默认就有一个演示用户
- 该用户继续沿用当前展示所需字段，如姓名、邮箱、头像文本、徽章文案和 Admin 访问能力
- 不再存在“从无用户切到有用户”的登录动作

### 登录与退出 API

现有 `loginAs` / `logout` 不再承担真实认证职责，处理方式如下：

- 优先移除不再使用的调用方
- 如果某些旧组件或测试短期仍依赖上下文签名，可先将 API 收敛为空操作或兼容实现
- 但项目行为上不再存在登录/退出流程

本次以“消除业务路径上的认证动作”为原则，而不是强行保留一套无意义的认证接口。

## 组件设计

### `AuthPage`

`AuthPage` 页面下线：

- 页面文件删除
- 路由接入移除
- “进入演示系统”按钮一并删除

### `UserHeader`

Header 改为默认展示演示用户态：

- 移除未登录时的“登录 / 注册”按钮
- 始终展示当前演示用户信息与用户菜单
- 保留个人中心与 Admin 入口
- 原“退出登录”操作不再保留认证语义，优先移除该按钮，避免出现“退出后又仍然可访问”的矛盾体验

### `LoginModal` 与 `UserOverlayContext`

登录弹窗链路整体下线：

- `LoginModal` 不再渲染
- `UserOverlayContext` 中与 `openLogin`、`afterLogin` 相关的流程移除
- 页面和组件不再通过弹窗完成登录

如果 `UserOverlayContext` 仍承载其他抽屉或弹层能力，应仅移除登录相关部分，避免波及无关功能。

### 受保护动作封装

以下封装不再承担认证拦截职责：

- `useRequireAuthAction`
- `useProtectedNavigation`

处理方式如下：

- 直接让动作继续执行或导航继续跳转
- 移除对 `/auth`、`state.from` 和 overlay 登录弹窗的依赖

## 测试设计

测试需要同步收敛到新的默认演示态行为：

- 删除“未登录访问跳转到 `/auth`”的断言
- 删除“点击进入演示系统后恢复来源页”的断言
- 删除或更新围绕登录弹窗、未登录拦截、鉴权跳转的测试
- 新增或保留“默认直接进入课程页 / 后台页”的断言

测试重点从“认证跳转正确”切换为“默认可访问”和“兼容路径无异常”。

## 风险与处理

### 风险 1：移除登录入口后，Header 或菜单出现空用户状态

处理方式：

- 使用固定演示用户作为默认状态来源
- 在删除认证入口前，先确保 `getUserPresentation()` 仍能拿到完整用户信息

### 风险 2：删除守卫后，旧测试大量失效

处理方式：

- 将相关测试按“登录跳转类”和“页面可访问类”分别收敛
- 仅保留与当前产品语义一致的断言

### 风险 3：登录弹窗下线影响其他 overlay 能力

处理方式：

- 只移除 `UserOverlayContext` 中的登录相关状态与回调
- 对其他抽屉、弹窗或浮层行为不做无关修改

### 风险 4：保留 `/auth` 兼容跳转会被误认为仍有 auth 页面

处理方式：

- 明确 `/auth` 只做跳转，不渲染登录 UI
- 文档、测试与代码命名中不再把它视为“登录页”

## 验证方案

实现阶段至少需要验证以下结果：

- 直接访问 `/courses`、`/recommendation`、`/profile`、`/admin` 时不再跳 `auth`
- `/auth` 不再显示登录页面内容
- Header 中不再出现“登录”“注册”“进入演示系统”等入口
- 登录弹窗不再可触发
- 用户菜单、个人中心和 Admin 入口仍然可以正常展示与跳转
- 路由测试、认证相关测试和受影响组件测试全部通过

## 实施顺序

建议按以下顺序执行：

1. 收敛路由，移除 `AuthPage` 挂载与 `RequireAuth` / `RequireRole` 接入
2. 收敛 `AuthProvider`，改为默认固定演示用户
3. 移除 `UserHeader`、`LoginModal`、`UserOverlayContext` 中的登录入口与登录弹窗
4. 清理 `useRequireAuthAction`、`useProtectedNavigation` 中的认证跳转逻辑
5. 删除 `AuthPage` 文件并更新相关测试
6. 运行路由、认证与组件测试，确认默认演示态行为稳定
