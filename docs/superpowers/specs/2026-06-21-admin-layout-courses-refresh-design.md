# Admin 后台布局统一与课程管理页改造设计

## 背景

当前项目的后台已经具备基础可用的 React 版本，包括：

- 左侧导航
- 顶部 Header
- 后台各管理页路由
- 课程、评价、院校、教师、学期、标签、用户、消息、日志等页面的基础表格骨架

但现有实现与参考样式仍有明显差距：

- 左侧导航的选中态过重，接近深色整块按钮，不符合原版的浅色弱强调风格
- Header 的层级、留白和细节样式仍偏厚，不够接近原版
- 页面主体存在重复的「页面标题 + 描述文案」，与 Header 左侧标题形成重复
- 课程管理页虽然已有搜索、筛选、表格和分页能力，但整体视觉结构与原版差异较大
- 当前课程 Mock 数据仅有 4 条，无法支撑接近真实后台的分页展示

本次工作的目标不是引入新交互模式，而是在保留当前后台 React 架构的前提下，统一后台壳层视觉规范，并优先将课程管理页改造成后续后台列表页的标准样板。

## 目标

- 统一后台全局壳层，包括侧边栏、Header 和主内容区容器
- 将页面标题统一收敛到 Header 左侧，移除页面主体中的重复标题与介绍文案
- 将课程管理页改造成「筛选工具栏 + 主操作按钮 + 表格 + 分页」的标准后台列表页
- 保留当前后台已有的新增、编辑、下线、本地筛选和分页能力
- 将课程 Mock 数据扩充到 18 条，并按分页展示
- 将课程管理页的分页口径固定为每页 10 条

## 非目标

- 不调整后台整体信息架构
- 不改动用户端页面
- 不接入真实后台 API
- 不在本次逐页精修其他后台业务页的表格列和筛选项
- 不重写现有抽屉、弹窗和本地 CRUD 行为逻辑

## 验收口径

本次改造完成后，应满足以下结果：

- 所有后台页共享统一的后台壳层视觉风格
- 页面主体不再重复显示大标题和介绍文案
- 课程管理页进入后台后可直接呈现原版风格的列表工作区
- 课程列表具备 18 条 Mock 数据，并以每页 10 条的方式分页
- 第一页显示 10 条，第二页显示剩余 8 条
- 搜索、筛选、分页、新增、编辑、下线等已有行为仍可正常工作

## 设计原则

### 1. 原版视觉优先

以用户提供的原版截图和现有 `docs/admin.html` 的后台风格为参考，优先还原布局比例、留白关系、导航强调层级和列表页结构，而不是继续沿用当前更重的后台视觉风格。

### 2. 全局统一，课程页先落地

本次先统一后台全局壳层，再把课程管理页作为首个标准页精修。其他后台页本次先继承新的壳层和内容区规范，不要求同步完成业务细节级的 1:1 调整。

### 3. 结构收敛，避免重复

页面标题只保留一个来源，即 Header 左侧标题。页面内容区聚焦业务操作本身，不再重复放置同名标题和说明块。

### 4. 延续现有组件体系

优先在现有 `AdminLayout`、`AdminScaffold` 和 `CoursesAdminPage` 上做重构和收敛，不重新发明一套新的后台组件体系，避免影响当前已恢复的后台行为逻辑。

## 方案选择

本次采用「全局壳层统一 + 课程页先落地」方案。

### 方案说明

- 统一 `AdminLayout` 的视觉规范和导航选中态
- 收敛 `AdminScaffold` 中的页面骨架，让它从「标题 + 描述 + 工具栏」改为「纯工具栏容器」
- 优先重做 `CoursesAdminPage` 的列表页视觉结构
- 扩充课程 Mock 数据，并沿用现有筛选分页逻辑

### 选择原因

该方案能够同时满足两个目标：

- 尽快把后台整体风格拉回到原版方向
- 为后续其他后台页提供可复用的标准页面结构

同时，它比「只修课程页」更适合作为后续迁移基础，又比「所有后台页一起精修」更可控。

## 影响范围

本次主要影响以下文件：

- `src/admin/AdminLayout.tsx`
- `src/admin/components/AdminScaffold.tsx`
- `src/admin/pages/courses/CoursesAdminPage.tsx`
- `src/admin/data/index.ts`

其中：

- `AdminLayout` 负责全局壳层统一
- `AdminScaffold` 负责页面内容骨架统一
- `CoursesAdminPage` 负责课程页业务结构对齐
- `admin/data/index.ts` 负责课程 Mock 数据扩充

## 布局设计

### 侧边栏

后台左侧导航保留当前信息架构，但调整视觉层级：

- 整体维持浅色背景、细边框和轻阴影
- 品牌区改成更轻量的展示，不再过分强调 logo 区块
- 导航项高度、圆角、内边距调整为更接近原版的紧凑比例
- 一级导航选中态从当前的深色整块胶囊改为浅紫底色方案
- 一级导航选中态增加左侧细竖条，形成与原版相近的当前页指示方式
- 未选中导航保持低对比度，hover 时仅做轻微背景变化

### 系统设置分组

保留当前的折叠分组方案，不改动信息架构：

- `系统设置` 作为父级导航继续存在
- 展开后显示 `消息管理` 和 `系统日志`
- 父级在展开或子项命中时保持弱高亮
- 子项采用缩进样式，但视觉强调强度低于一级导航

### Header

Header 保留现有功能，但收敛视觉样式：

- 左侧只保留当前页面标题
- 移除不必要的额外文案层级
- 右侧继续保留通知按钮和管理员菜单
- 头像、分隔线、边框和阴影改得更轻，贴近原版
- Header 与内容区之间继续使用底边线分隔，减少厚重卡片感

### 主内容区

主内容区改成标准后台工作区容器：

- 保持统一的左右留白
- 页面主体使用更直接的纵向流布局
- 不再为每个页面额外渲染「标题 + 描述」块
- 页面进入后默认先看到工具栏和表格主体

## 页面内容规范

后台列表页统一遵循以下内容结构：

1. 顶部工具栏
2. 数据表格卡片
3. 底部分页区

其中：

- 工具栏承载搜索框、筛选项和主操作按钮
- 数据表格作为主体信息区，直接展示列表结果
- 分页区位于表格卡片底部，展示总数和分页器

这套结构会通过更新 `AdminScaffold` 来承载，后续其他后台页只需继续使用同一套工具栏和表格骨架即可。

## 共享组件设计

### `AdminLayout`

`AdminLayout` 的职责保持不变，但样式和局部结构做以下调整：

- 重写导航项选中态样式
- 调整侧栏宽度、品牌区、底部版本区和 Header 视觉细节
- 保持通知抽屉、管理员菜单、退出登录和切换到用户端能力不变
- 保持页面标题仍由路由映射得到

### `AdminPageFrame`

`AdminPageFrame` 从当前的「页面标题区 + 工具栏 + 内容区」改为「工具栏 + 内容区」：

- 移除 `title` 和 `description` 的可视渲染
- 工具栏继续接收搜索、筛选和主按钮
- 保持 API 尽量兼容，避免一次性影响全部后台页面

兼容方式如下：

- 允许页面仍然传入 `title` 和 `description`
- 但该组件不再渲染这两部分内容
- 后续其他页面可以逐步移除冗余参数，而不会阻塞本次改造

### `AdminTableCard`

表格卡片保留当前职责，但样式会向原版收敛：

- 圆角更克制
- 表头背景更轻
- 边框与阴影降低存在感
- 卡片整体更像原版的纯白工作面板

### `AdminFooterPagination`

分页区沿用现有能力，但文案和布局会更贴近原版：

- 显示总条数
- 继续使用当前通用 `Pagination` 组件
- 调整边距和边框，避免与表格主体割裂

## 课程管理页设计

### 页面定位

课程管理页作为后台默认首页，需要成为后续后台列表页的模板页。页面不再承担介绍性质的说明，只承担实际管理工作流。

### 工具栏结构

课程管理页工具栏结构固定为：

- 左侧搜索框
- 院校筛选
- 状态筛选
- 右侧 `新增课程` 按钮

布局规则如下：

- 宽屏下优先横向排布
- 搜索框占据主要宽度
- 两个筛选器在搜索框右侧顺序排列
- `新增课程` 按钮固定在工具栏右侧
- 窄屏下允许自然换行，但不改变字段顺序

### 表格结构

课程管理页保留以下列：

- 课程代码
- 课程名称
- 所属院校
- 学分
- 授课教师
- 助教
- 课程描述
- 状态
- 操作

其中：

- 状态列继续使用 `AdminStatusBadge`
- 操作列继续保留 `编辑` 与 `下线`
- 本次不新增批量操作

### 表格视觉

课程管理页表格会向原版风格收敛：

- 表头更浅、更紧凑
- 行高适度压缩
- 课程名称保留主标题风格
- 状态标签使用轻量色块
- 操作按钮不再过于抢眼，以低干扰为主

### 抽屉与确认弹窗

保留当前课程页的新增 / 编辑抽屉和下线确认弹窗：

- 不改变字段结构
- 不改变保存和下线逻辑
- 只在必要时微调按钮样式，使其与新的列表页风格一致

## 数据设计

### 课程数据

课程 Mock 数据由当前的 4 条扩充为 18 条，保持与现有类型兼容：

- 字段结构不变
- 继续包含搜索用的 `searchText`
- 继续包含状态文本和状态色调
- 数据分布覆盖多个院校和多种状态，确保筛选器可用

### 分页口径

课程管理页分页参数调整为：

- `pageSize = 10`
- `totalItems = 18`

因此课程页分页结果为：

- 第 1 页：10 条
- 第 2 页：8 条

该口径用于接近原版列表页「一屏更多数据」的密度。

## 数据流与交互

本次不改动课程页已有的本地交互行为：

- 搜索仍通过 `matchesText` 完成
- 院校和状态筛选仍通过 `matchesSelect` 完成
- 分页仍通过 `useAdminPageFilters` 完成
- 新增、编辑和下线仍通过 `useAdminEntityCollection` 驱动

本次仅调整：

- 页面视觉结构
- 数据规模
- 每页条数配置

这样可以把风险控制在样式与页面骨架层，不影响已恢复的后台可操作性。

## 后续页面迁移规则

本次课程页完成后，其他后台列表页后续应遵循同一规则：

- 页面标题只放在 Header 左侧
- 主体内容直接从工具栏开始
- 默认结构为「筛选区 + 主操作按钮 + 表格 + 分页」
- 如果页面没有新增按钮，可只保留搜索与筛选
- 如果页面没有分页，也应保留同一张表格卡片容器

这意味着课程管理页会成为后续页面迁移的样板，而不是一次性的局部修补。

## 风险与处理

### 风险 1：移除页面标题后影响其他后台页可读性

处理方式：

- 标题仍然保留在 Header 左侧
- 本次先统一壳层，再逐页观察其他后台页的实际视觉效果
- 页面标题参数暂不删除，只是不再显示，降低回退成本

### 风险 2：`AdminPageFrame` 修改会波及全部后台页

处理方式：

- 仅收敛其可视结构，不大改 props 形态
- 保留筛选、搜索、主按钮和子内容插槽行为
- 避免对各后台页产生逻辑级破坏

### 风险 3：课程数据扩充后影响筛选与分页预期

处理方式：

- 保持现有筛选逻辑不变
- 让数据分布覆盖多个院校和多种状态
- 通过手动验证第一页、第二页以及筛选后的分页重置行为

## 验证方案

实现阶段需要至少验证以下内容：

- 进入任一后台页时，Header 左侧显示页面标题，主体内不再重复显示标题和描述
- 左侧导航选中态符合新的弱强调风格
- `系统设置` 折叠分组在命中子路由时仍能正确展开和高亮
- 课程管理页工具栏、表格和分页结构符合目标样式
- 课程列表总数据为 18 条，默认每页 10 条
- 搜索、院校筛选、状态筛选和分页切换可协同工作
- 新增、编辑和下线操作在新样式下仍然可用

## 实施顺序

建议按以下顺序执行：

1. 调整 `AdminLayout`，统一侧边栏、Header 和主内容区样式
2. 调整 `AdminScaffold`，移除页面主体中的标题和描述渲染
3. 调整 `CoursesAdminPage`，对齐课程页工具栏和表格布局
4. 扩充 `admin/data/index.ts` 中的课程数据至 18 条
5. 将课程页 `pageSize` 调整为 10
6. 完成回归验证和样式细修
