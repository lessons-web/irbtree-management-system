# 用户端 React 化迁移设计

## 背景

当前项目已经完成 Vite + React + TypeScript + Tailwind 的基础接入，但用户端界面仍是一个临时原型。原始设计稿和交互原型已经存在于 [docs/index.html](file:///Users/luffyzh/luffyzh/github/irbtree/irbtree-management-system/docs/index.html)，其内容并不是单一首页，而是一个完整的用户端前台，包含首页、课程列表、课程详情、个人中心、推荐入口，以及登录弹窗、评价抽屉、已修课程抽屉等核心交互。

本次工作目标不是重新设计，而是将现有 HTML / CSS / JS 原型迁移为可维护的 React 实现，并尽量保留原有视觉结构、交互路径和内容组织方式。

## 目标

- 将 [docs/index.html](file:///Users/luffyzh/luffyzh/github/irbtree/irbtree-management-system/docs/index.html) 的用户端完整迁移到 React
- 保留原始设计中的视觉层级、文案结构、色彩、圆角、阴影、悬浮效果和抽屉/弹窗动效
- 将原来的 `onclick`、DOM 查询和显隐切换改造成 React 路由、组件状态和事件处理
- 使用本地 mock 数据完成首期页面和交互复刻，不在本期接入真实后端
- 保留桌面端右下角“课程咨询”入口，不实现不在一期范围内的移动端浮动图标

## 非目标

- 本期不迁移 [docs/admin.html](file:///Users/luffyzh/luffyzh/github/irbtree/irbtree-management-system/docs/admin.html)
- 本期不实现真实登录、评价提交、收藏、点赞、推荐算法、消息通知等服务端能力
- 本期不做移动端适配
- 本期不对原始视觉做二次设计或信息架构重做

## 技术方案

### 总体方案

采用“视觉尽量原样保留，结构改为 React 路由 + 组件化”的迁移方式：

- 使用 React Router 承载主要页面，而不是继续用单页中的 tab 显隐
- 使用 Tailwind 继续表达样式，尽量复用原 HTML 中已经验证过的 class 结构和视觉细节
- 将弹窗、抽屉、标签、评分、列表筛选、分页等逻辑迁移为 React 组件状态
- 所有展示数据先放在本地 mock 数据文件中，保证页面行为可运行且便于后续替换为真实接口

### 选型理由

相比“把原始 HTML 直接塞进一个 React 组件再用状态控制显示/隐藏”的方案，路由化拆分更适合后续演进：

- 页面边界更清晰，后续接后端不需要重构整体结构
- 课程详情、个人中心、推荐页可以天然拥有独立 URL
- 抽屉与弹窗保留为局部状态，页面结构不会被全局 DOM 操作污染
- 维护成本远低于继续堆叠一个大组件

## 全局交互范围

### Header 与导航

- 使用统一的用户端 Layout 包裹所有前台页面
- 导航项通过路由高亮，不再使用原始的 `switchTab`
- 登录 / 注册按钮保留
- 登录后态先用 mock 用户信息驱动

### 登录弹窗

- 原 HTML 中的登录弹窗改造成 React Modal 组件
- 包含打开、关闭、遮罩点击关闭、状态切换
- 登录行为为 mock，不接真实鉴权

### 评价抽屉

- 原 `review-drawer` 改造成 React Drawer
- 打开时展示课程名、学年学期选择、评分区、标签区、评论输入区
- 抽屉开关、遮罩层和表单内容由组件状态维护
- 提交后先走前端 mock 成功反馈

### 已修课程抽屉

- 原 `completed-course-drawer` 改造成 React Drawer
- 支持 mock 的添加、关闭和列表刷新
- 用于驱动个人中心中的已修课程展示

### 课程咨询悬浮入口

- 保留桌面端右下角悬浮咨询入口
- 不实现截图中不在一期范围内的移动端悬浮图标

## 信息架构与组件拆分

建议按“页面 + 共享组件 + mock 数据 + hooks”组织：

- `src/app/router/*`：路由定义
- `src/layouts/UserLayout.tsx`：前台统一布局
- `src/pages/home/*`：首页
- `src/pages/courses/*`：课程列表页
- `src/pages/course-detail/*`：课程详情页
- `src/pages/profile/*`：个人中心
- `src/pages/recommendation/*`：推荐页
- `src/components/common/*`：按钮、标签、模态框、抽屉、分页等通用组件
- `src/components/user/*`：Header、Footer、CourseCard、SearchBar、RatingPanel 等用户端组件
- `src/data/*`：课程、评论、用户、推荐结果、筛选项等 mock 数据

首期不强求拆分到极细粒度，但必须避免再次将所有页面堆回单一 `App.tsx`。

## 数据策略

### 首期数据来源

全部使用本地 mock 数据，来源以原 HTML 中已有内容为准，包括：

- 热门课程卡片
- 完整课程列表
- 课程详情中的基础信息、教师、评分、评论
- 个人资料、收藏、点赞、回复、已修课程
- 推荐页结果

### 数据组织原则

- 展示数据与组件实现分离
- 同一份课程数据在首页、列表页、详情页之间复用
- 所有“提交类操作”先通过本地 state 或 mock handler 更新展示结果

## 视觉还原要求

- 尽量保留原设计中的 Tailwind 类语义和层级
- 保留主要色值：`primary = #4F46E5`、`secondary = #6366F1`
- 保留原设计中的圆角体系、阴影层次、边框弱对比和 hover 动效
- 保留 Hero 背景模糊装饰、评分标签、卡片 hover 抬升等细节
- 保留抽屉与弹窗的进入/退出动画

允许的调整仅限于：

- 为适配 React 组件拆分做最小结构调整
- 为可维护性将原始重复代码抽成可复用组件
- 为 TypeScript 类型安全补充必要的数据定义

## 可维护性要求

- 不再使用直接 DOM 查询、`onclick` 内联事件、手动 class 切换
- 不再依赖 CDN Tailwind 和浏览器全局脚本
- 所有交互都通过 React state、props、hooks 和路由管理
- 页面内容拆分为独立文件，避免形成新的超大组件

## 验证标准

完成用户端 React 化后，应满足以下标准：

- 用户端主要页面均能通过路由访问
- 首页、课程列表、课程详情、个人中心、推荐页视觉与原 HTML 高度一致
- 登录弹窗、评价抽屉、已修课程抽屉可打开、关闭并完成 mock 交互
- 热门课程、课程列表、详情页跳转链路可走通
- 构建通过，Lint 通过，无新增诊断错误
