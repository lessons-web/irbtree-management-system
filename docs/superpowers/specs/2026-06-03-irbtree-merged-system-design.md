# IRBTree 合并系统设计（评课 + 选课 + 学习 + 学员管理）

## 1. 背景

当前仓库内存在两套 Demo 与两份核心需求：

- 学员管理系统 PRD：教务管理（替代 Excel）、学员学习入口（课件/刷题/模考）、权限/有效期/安全等。
  - 见：[prd/红黑树学员管理系统 PRD.md](../../../prd/%E7%BA%A2%E9%BB%91%E6%A0%91%E5%AD%A6%E5%91%98%E7%AE%A1%E7%90%86%E7%B3%BB%E7%BB%9F%20PRD.md)
- 评课系统与选课推荐 PRD：课程评价、选课推荐模块与个人中心闭环。
  - 见：[docs/Course_Selection_Recommendation_PRD.md](../../Course_Selection_Recommendation_PRD.md)

目标是将两套系统合并成一个 Web 产品：同一入口、同一账号体系，前台提供「评课 / 选课 / 学习」三大模块，后台在既有评课后台基础上新增学员付费与学习内容管理。

## 2. 设计目标与非目标

### 2.1 设计目标

- 一个 Web 入口：首页作为引流门户。
- 前台三大模块：评课 / 选课 / 学习，配套「我的」统一个人中心。
- 账号体系统一：前台与后台共用会话与用户体系，通过角色控制后台访问。
- 数据模型可落地：避免“课程”概念混淆，能复用既有评课数据为学习导流。
- 先信息架构后功能：先把路由、布局、边界、数据模型与占位页落地，再逐步完善功能。

### 2.2 非目标（本阶段不做）

- 不在本阶段实现真实支付闭环（只做缴费流水/开通/到期拦截与提示）。
- 不在本阶段实现 AI 选课推荐的完整链路（可先规则筛选 + 占位输出）。
- 不在本阶段实现自动判题与自动评分（模考可先做倒计时与复盘占位）。

## 3. 产品信息架构（C 端）

### 3.1 顶层导航

固定结构：

- 首页（引流门户）
- 评课（课程评价）
- 选课（课程筛选与推荐）
- 学习（学员学习入口）
- 我的（统一个人中心）

### 3.2 首页（引流门户）

首页同时承载两类摘要信息：

- 评课摘要：热门课程、最新评价、写点评入口。
- 学习摘要：登录后展示我的课程、到期提醒、快捷入口（课件/刷题/模考）。

### 3.3 评课模块

- 课程列表（筛选/排序）
- 课程详情（维度评分、标签、评价列表）
- 写点评（抽屉/弹层）

### 3.4 选课模块

- 规则筛选：院校/学期/标签/维度（难度、作业、给分、收获等）
- 推荐结果：先规则推荐，后续再接 AI 推荐

### 3.5 学习模块（学员）

- 我的课程：权限/有效期/状态（学习中/已过期/未开通）
- 课程内：课件 / 刷题 / 模考
- 未开通或已过期：仅提示与引导（不做支付）

### 3.6 我的（统一个人中心）

一个入口内分区承载数据：

- 账号信息：基础资料、学校/邮箱、设置
- 评课：我的评价 / 收藏 / 点赞
- 选课：我的计划 / 已修课程（用于过滤推荐）
- 学习：我的课程 / 错题本 / 模考记录

## 4. 后台信息架构（B 端）

### 4.1 路径与登录

- 后台固定路径：`/admin`
- 登录方式：复用前台登录态（同一会话）
- 权限要求：访问 `/admin/*` 需要 `admin` 或 `teacher` 角色

### 4.2 菜单分组

在现有评课后台信息架构上新增分组：

- 数据概览：工作台（Dashboard）
- 评课治理（沿用）：课程管理 / 评价管理 / 院校管理 / 教师管理 / 学期管理 / 标签管理
- 学员付费（新增）：学员管理（开通课程/有效期/备注）/ 缴费流水
- 学习内容（新增）：课件管理 / 题库管理 / 模考管理
- 系统（沿用）：用户管理 / 系统设置 / 系统日志

## 5. 访问控制与权限边界

### 5.1 前台访问策略

- 首页 / 评课 / 选课：匿名可浏览
- 写评、收藏等用户动作：需要登录
- 学习：需要登录且需要有效的课程权限（Enrollment 未过期）

### 5.2 后台访问策略

- `/admin/*`：仅 `admin` / `teacher` 角色可访问
- 推荐实现方式：统一鉴权中间件 + 路由守卫，前后端都基于同一套用户会话判断

## 6. 共享数据模型（关键决策）

### 6.1 两张课程表

为避免“课程”语义混淆，采用两张课程表：

- `UniversityCourse`：评课/选课使用的高校课程
- `ProductCourse`：学习/付费使用的红黑树产品课程

### 6.2 严格 1:1 课程关联表

为了复用评课系统的现成数据（评分、标签、评价），并将其导流到学习模块，引入 1:1 关联表：

- `CourseLink`：`productCourseId` ↔ `universityCourseId`
- 约束：
  - `productCourseId` 唯一
  - `universityCourseId` 唯一

用途示例：

- 学习课程页展示对应高校课程的评分与评价摘要。
- 评课课程页展示「对应红黑树学习课程」入口（如用户有权限则直达学习内容）。

### 6.3 领域实体边界（建议字段）

跨域共享：

- `User`：`id`, `email`, `schoolId?`, `roles[]`（`student` / `teacher` / `admin`）, `createdAt`
- `Tag`：`id`, `name`, `type`（`review` / `recommend` / `learn`）, `createdAt`
- `School`：`id`, `name`, `emailDomains[]`
- `Term`：`id`, `schoolId`, `name`, `startAt?`, `endAt?`

评课域：

- `Review`：`id`, `universityCourseId`, `userId`, `ratings{}`, `tags[]`, `text`, `createdAt`

学习/付费域：

- `Enrollment`：`id`, `productCourseId`, `userId`, `expiresAt`, `status`
- `Payment`：`id`, `userId`, `productCourseId?`, `amount`, `paidAt`, `method`, `note`

学习内容子资源（后续逐步细化，不在本设计中锁死字段）：

- `Material`（课件）
- `Problem`（题目）
- `Exam`（模考/试卷）

## 7. 路由草案（前台与后台）

### 7.1 前台路由（建议）

- `/`：首页
- `/review/*`：评课模块
- `/recommend/*`：选课模块
- `/learn/*`：学习模块
- `/me/*`：个人中心
- `/auth/*`：登录/注册/找回密码

### 7.2 后台路由（建议）

- `/admin` → `/admin/dashboard`
- `/admin/reviews/*`
- `/admin/students/*`
- `/admin/content/*`
- `/admin/system/*`

## 8. 迁移策略（从 Demo 到统一工程）

- 将 `docs/*.html` 的静态原型作为 UI 参考，逐步收敛到 `src/` 内的真实页面与组件。
- 将 `src/App.tsx` 中的“状态切换三端视图”升级为真实路由与布局拆分。
- 优先落地“壳与导航 + 占位页 + Mock 数据”，确保合并方向可持续迭代。

## 9. 验收标准（信息架构阶段）

- 前台存在稳定的顶层导航：首页 / 评课 / 选课 / 学习 / 我的。
- `/admin` 可访问（登录态复用），并有侧边栏分组：评课治理 / 学员付费 / 学习内容 / 系统。
- 数据模型边界明确：`UniversityCourse` 与 `ProductCourse` 分离，且 `CourseLink` 为严格 1:1。
- 学习模块具备“登录 + 权限/有效期”拦截占位能力（无权限时明确提示）。
